# B109 Guided Nexus and Steam Release Center — Implementation Plan

> **For Agent:** REQUIRED SUB-SKILL: use `executing-plans`; execute in reviewable batches and update this
> record after every batch.

**Goal:** replace the incomplete B9 one-button release action with separate guided, verified Nexus and Steam
workflows while preserving explicit source identity and platform-specific truth.

**Architecture:** a pure release engine extends the existing artifact/ZIP/catalog capabilities; authenticated
routes create and validate artifacts only inside configured Forge release state; the React Release Center owns
the guided stage model; the installed host supplies user save/file pickers and a visible, not-auto-executed Steam
terminal command. Source and live game folders are never implicit output targets.

**Tech stack:** TypeScript, Express, React, Node filesystem/zlib/crypto, VS Code extension API, Playwright,
existing runtime-oracle and route-integration harnesses.

## PLAN

- **Bounded unit:** B109 only—the two platform release experiences and their required output/verification
  infrastructure. Kimi R1-R21 execution remains tracked in the sibling ledger and B110.
- **Assumptions:** the user selects Guided by default; Express begins local preparation from the platform button and
  collapses passed explanations but never skips a gate or external confirmation; Steam publication stays interactive;
  Nexus upload stays manual; `WorkshopTool.exe` may be absent and that is a required clean failure.
- **Authoritative references:** ADR-F4; capability map; existing `artifactPipeline`, `artifactPackager`,
  `modDistribution`, validation, readiness, Studio settings, and native bridge; Egosoft Workshop documentation;
  Nexus file-submission/quarantine documentation.
- **In scope:** explicit Nexus/Steam buttons; step-by-step stage results; complete disk-backed bytes; manifest and
  preview checks; user-selected Nexus ZIP/Steam backup ZIP through native save UI; atomic+hash-verified export;
  Steam command rendering and visible terminal handoff; post-tool result validation; Express setting; guides.
- **Out of scope:** automatic Nexus login/upload; an unattended Steam upload; Steam credentials; Workshop legal
  agreement acceptance; visibility changes; screenshot capture; real-mod/game-directory writes; general R1-R21.
- **Risks and authorization boundaries:** output writes occur only after user selection; source Workshop-id adoption
  requires a separate explicit confirmation; Steam command is inserted but not executed; no cloud action occurs in
  automated tests. Rollback deletes only B109-owned scratch/output fixtures and restores the prior source diff.
- **Rollback/checkpoint:** clean `72ec4aa`; all tests use temp roots; previous public 0.0.58 VSIX is the installed
  rollback artifact; no live mod/game path is a test target.
- **Acceptance criteria:**
  1. Nexus packages every planned source/generated byte under exactly one mod root, writes to a selected `.zip`,
     and proves ZIP structure, CRC, names, hashes, and independent extraction.
  2. Steam stages the complete plan through Forge's existing verified CAT/DAT packager, rejects invalid
     manifest/folder/preview/tool states with the failing stage, constructs the official publish/update command,
     never executes automatically, and validates unchanged CAT/DAT plus Workshop metadata after a fixture tool run.
  3. UI exposes two individual buttons and stage steppers; Guided/Express behavior is truthful and persisted.
  4. Every mutation is explicit-source, atomic or transaction-backed, and represented in agent history.
  5. Installed Antigravity visibly exercises both flows, including one invalid target/tool negative.
- **Required validation:** focused pure selftests; route integration; independent `Expand-Archive`; typecheck; lint;
  runtime oracle sweep; full isolated E2E; production build; extension stage/build/package/probe; installed-host UI.
- **Negative paths:** red project, missing disk source, traversal/duplicate/oversize ZIP input, unsafe output extension,
  output changed after selection, invalid Steam folder name, absent/wrong tool, invalid preview, publish/update mismatch,
  CAT/DAT corruption, tool nonzero exit, and cancelled native dialog all produce no false success.
- **Unavailable validation:** real Steam cloud upload is authorization-gated and X Tools is not currently installed on
  this machine. A fixture executable proves orchestration; installed X Tools help/preflight becomes an additional gate
  if the user installs it. Nexus server scanning happens only after the user uploads and is not locally claimable.
- **Evidence locations:** this record; `vscode-extension/evidence/<release>/`; isolated test output; capability-map and
  ROADMAP deltas at close.

- **Batch 2.13 verifier-coupling correction:** the post-tool verifier still reconstructed staging from `modId` and
  only checked expected files for missing/changed bytes. It now resolves the report's separately preserved folder

  rebuilds the current artifact plan and requires the exact non-manifest path/size/hash set, so unexpected additions

- **Batch 2.15 native-output correction:** installed Save As defaulted to the internal artifact directory and could
  therefore suggest the source ZIP itself, which the verifier correctly refuses. The default now points at the
  configured workspace root. Existing `.zip` output must be a regular non-link file; a directory or link is refused
  before rollback-safe overwrite. Extension build and the expanded native selftest pass.
- **Batch 2.16 receipt-authority correction:** the export receipt route previously accepted any syntactically valid
  hash/size and a deploy-scoped agent could call it, so the ledger row did not prove a user output matched a prepared
  release. Receipts now carry the internal artifact path, re-run the same report/path/regular-file/hash/size verifier
  used for download, and require the submitted saved-byte receipt to match it. The route is Studio-session-only
  because an agent cannot assert that a native/browser Save As completed. Forged-receipt and agent-scope negatives
  are authored; agent-key policy is 25/25 green.
- **Batch 2.17 output-root containment correction:** release output construction previously joined lexical paths
  below `.forge-builds/releases` without rejecting an existing junction. A shared resolver now canonicalizes the
  configured workspace, walks every platform-root component, rejects links/non-directories, and proves containment.
  Nexus/Steam prepare, artifact download, receipt verification, and post-tool verification all use it. The isolated
  route fixture redirects `releases` through a junction and asserts a named refusal plus zero outside writes.
- **Batch 2.18 guarded Workshop-metadata adoption:** the design required a first-publish source-diff/adoption close,
  but the implemented UI stopped at `sourceManifestAdoptionRequired:true`. Steam preparation now records a contained
  regular source manifest and its raw-byte SHA-256. After exact post-tool verification, a session-only adoption route
  first returns the complete bounded before/after content without writing. Apply requires that preview's source hash
  and Workshop id, rechecks the original preparation hash, refuses concurrent source edits, writes atomically, hashes
  the final bytes, and marks the report `VERIFIED_AND_ADOPTED`. The UI presents the diff and a separate confirmed
  write action, then requires re-import. Route negatives for preview non-mutation and stale-source CAS are authored;
  agent history remains 67/67 and scope policy 25/25.
- **Batch 2.19 adoption outcome-truth correction:** source replacement and release-report update were initially in
  one catch, which could label a completed source write as failed if only the report write failed. Final source bytes
  are now independently rehashed; mismatch triggers restoration of the exact original raw bytes. Once the source is
  verified, a later report failure returns `PARTIAL`, names `adoption-report`, says the source is already changed, and
  explicitly warns against retrying. The UI treats that as written-but-unreported and still requires re-import.
- **Batch 2.20 manifest-integrity correction:** post-tool verification excluded `content.xml` from byte identity but
  did not constrain changes inside it, contradicting the recorded “id-only mutation” claim. Installed Workshop
  manifests and Egosoft's guide establish `id`, `lastupdate`, and `sync` as tool-managed attributes. Preparation now
  records the exact staged manifest; verification canonicalizes only those three attributes and requires every other
  attribute plus all surrounding XML/body content to remain invariant. Author/version/description/dependency drift
  now fails with `STEAM_POST_TOOL_MANIFEST_DRIFT`. Pure coverage is 22/22 and the route negative is authored.
- **Batch 2.21 terminal-command authority correction:** the server emits a fully single-quoted PowerShell command,
  but the native parser still accepted a looser historical shape and did not bind the parsed executable or `-path`
  value to the separately supplied tool/stage fields. The bridge now parses the exact generated grammar, binds both

  `-buildcat` and all multiline input. The host re-inspects the selected PE-shaped `WorkshopTool.exe` immediately
  before creating the visible terminal. Native proof is 45/45. The same audit capped source manifests at 1 MB before
  the guarded adoption path hashes or reads them.
- **Batch 3 runtime reconciliation and correction:** the first isolated route run showed that required release
