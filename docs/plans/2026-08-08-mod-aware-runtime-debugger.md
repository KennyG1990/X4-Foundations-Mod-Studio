## PLAN

- Bounded unit: replace tail-and-name matching inside the existing watcher owner with a durable log-session engine, deterministic active-mod ownership, multiline incident parsing, exact source/node mapping, and an incident-focused Playtest UI. Preserve the existing watcher routes and polling owner for compatibility. `0.0.67` was published for installed-product validation, but that validation exposed a release-blocking active/installed owner-correlation and retention defect; the accepted stable release must therefore be a corrective version newer than `0.0.67`.
- Assumptions and unresolved facts:
  - X4 emits useful evidence for structural/runtime failures, but no log watcher can detect every semantic failure that emits no evidence. The measurable target is at least 99% `attributed | deliberately excluded | explicit unknown` coverage across the real-log/fixture corpus, never a false clean result.
  - The active log can exceed 256 KiB and can rotate, truncate, or change X4 profile while a sidecar is alive or stopped.
  - Workspace display name, `content.xml` id, source-folder name, deployed-folder name, MD script identity, Lua module path, and historical diagnostic tags may all differ. Display-name substring matching is evidence only, never ownership authority.
  - Existing optional FORGE-WATCH/FORGE-STATE/probe and expected-cue carriers are reused. Automatic arbitrary source instrumentation is out of this release; declared expected steps must be reported as observed, missing, or evidence-unavailable rather than inferred green.
- Authoritative references:
  - ADR-F3 (debuglog protocol first, optional read-only companion probe, no bridge dependency), ADR-F4 (source/deployment ownership split), and ADR-F5 (immutable workspace authority).
  - Existing `buildDebugWatcherBrief`, `getGameLogStatus`, `buildWorkspaceFileManifest`, `luaRuntimeLog`, `liveLogNav`, `cueLineage`, `forgeWatch`, and `forgeState` owners.
  - X4's installed/unpacked files and real `debuglog.txt`; X4 XSDs for structural explanation, with runtime-only constraints kept as governed Forge rules rather than falsely attributed to XSD.
  - GitHub #14 and #35; BACKLOG B96/B114; capability-map deltas.
- In scope:
  - A bounded durable cursor/session store keyed by immutable workspace identity and selected log-file identity.
  - Incremental ingestion from session offset with UTF-8 and partial-line safety; profile change, truncation, and rotation start a named new segment without erasing retained incidents.
  - A runtime ownership index derived from stable workspace/content/deploy identity plus owned files, MD scripts/cues/libraries, AI scripts, Lua paths/modules, and source spans. Historical aliases may supplement but never override exact ownership.
  - Multiline incident grouping, deterministic engine-vs-authored classification, attribution confidence/reason, repetition collapse, unrelated-mod exclusion counts, and explicit ambiguous/unknown states.
  - Direct `extensions/<folder>/<file>(line)` and Lua/MD/AI context mapping to the deepest modeled node; honest file/line fallback when no node exists.
  - Deterministic authored-emitter provenance: when a mod-authored tagged diagnostic has no path, search the bounded active/other source manifests for the exact emitted message and tag helper, then confirm a unique active emitter, exclude a unique other-mod emitter, preserve bounded candidates for collisions, or remain explicitly unresolved.
  - One deterministic cause/impact/next-action explanation per known incident class, with governed provenance where available and generic evidence-only wording otherwise.
  - Backward-compatible watcher status/brief responses plus detailed session, coverage, ownership, and incidents.
  - Playtest UI preserving the old watcher's concise information hierarchy: one status summary, compact actionable active-mod errors/warnings, expected cue/activity health, and progressive disclosure for attribution/coverage/session/evidence internals. Restore click-through navigation: deepest Forge-node highlight for modeled MD/XML, exact native file/line opening for confirmed active source without a canvas node, and no unsafe navigation for ambiguous ownership.
  - Comprehensive changelog, stable package, Open VSX publication, public-download hash/readback, public artifact installation, Antigravity reload, rendered interaction proof, and running-sidecar provenance.
- Out of scope:
  - A separate daemon, provider product, CLI, bridge dependency, or AI authority.
  - Claiming breakpoints, variable inspection, or omniscient detection of silent game semantics.
  - Mutating the user's real mod or game installation for tests. Running-X4 proof uses read-only real-log evidence and/or a purpose-built scratch/probe mod only.
  - Changing unrelated W3 receipt/governance work.
- Likely affected resources:
  - New pure/store modules and selftests under `src/lib/`.
  - `server.ts` watcher/deploy integration and runtime selftest registration.
  - `src/components/PlaytestWorkspace.tsx`, `src/App.tsx`, and existing navigation helpers.
  - Focused route/oracle/E2E tests, graphify output, release metadata, and durable close records.
- Risks and authorization boundaries:
  - Log privacy: persist only bounded incident evidence needed for debugging, never the complete game log or credentials; redact home/profile prefixes in public UI where ownership does not require them.
  - Disk growth: bounded store, deduplicated incidents, atomic writes, explicit corruption refusal/recovery, and no write path under a mod/game/corpus root.
  - False attribution: exact path/script/module ownership outranks aliases; collisions become `ambiguous`, never active-mod certainty.
  - Watcher load: incremental reads and bounded parsing only; no repeated full-file polling.
  - Publishing and installing are explicitly authorized by the user. Real mod/game writes are not required for this unit.

1. Stable identity: a workspace named `AiLive` with `content.xml`/deployed folder `x4_ai_influence` attributes the real direct-path error to the active mod without any `x4_ailive` substring.

5. Attribution: exact active ownership is confirmed; known unrelated extension incidents are excluded; shared/colliding evidence is ambiguous; unsupported evidence is explicit unknown. No matched lines and zero failures render differently.
6. Severity: routine mod-authored `[=ERROR=]`, `[AICHAT]`, and equivalent historical aliases do not become engine failures; a genuine direct-path/runtime fault still does.

Ambiguous/unknown ownership never opens a guessed file or fabricates a node.
8. A unique other-owner emitter is excluded, duplicate emitters remain ambiguous with bounded candidate locations, and no match remains unresolved.
9. Explanation: every shown incident states classification reason, likely impact, next bounded action, and evidence/provenance. Unknown classes say what is unknown. Routine authored telemetry must not receive a generic engine-failure impact/action merely because it used `DebugError` or `[=ERROR=]` as its output channel.
10. Information hierarchy: the default watcher surface is readable at a glance—one status summary and compact actual-error rows with message, source, count, and click target. Informational authored activity is separated from errors. Repeated cause/impact/action text, raw samples, attribution evidence, coverage arithmetic, identity, and session provenance remain available under collapsed progressive disclosure rather than dominating the primary surface.
11. Repetition/noise: equivalent occurrences collapse with count/first/last evidence; unrelated incidents are hidden from the main list but their count and attribution state remain visible.
12. Expected flow: existing declared expected cues/markers report observed, missing, or unavailable against the current segment; absence never becomes success.
13. Coverage metric: the real-log plus synthetic hostile corpus reaches at least 99% recognized-or-explicit-unknown, with zero silently dropped candidate failures and zero known-unrelated incidents shown as active-mod incidents.
14. Compatibility/performance: existing watcher/readiness consumers retain their required fields; polling performs incremental bounded work; corrupt state and unreadable/rotated logs fail honestly without taking down the API.
15. Privacy: rendered payloads and copyable artifacts redact the exact user-home prefix while internal machine operations retain the exact selected log path; similarly prefixed sibling paths are not misclassified as descendants.
16. Product proof: typecheck, lint, focused selftests, routes, runtime oracle sweep, full verdict-parsed E2E, build, precommit, graph refresh, staged-app probe, VSIX inspection, packaged/install parity, and installed Antigravity interaction all pass.

Public proof: Open VSX reports the new stable version; the downloaded public VSIX matches the published local artifact; Antigravity installs/reloads that public artifact; its manifest and running sidecar cwd/version identify the new public version; the rendered debugger shows the real active workspace identity and retained attributed incident.
