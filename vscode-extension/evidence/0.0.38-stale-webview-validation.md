# X4 Forge Studio 0.0.38 — retained webview validation

Date: 2026-07-25

Status: VERIFIED

## Regression under test

An already-open X4 Forge Studio webview could remain bound to a dead managed-sidecar port after the extension host or backend restarted, leaving Antigravity with a blank Studio even though a replacement sidecar was healthy.

- Package inspection — PASS: 2,091 entries, zero forbidden entries, manifest version 0.0.38, activation events `onStartupFinished` and `onWebviewPanel:x4forge.studio`.

## Installed Antigravity proof

The local 0.0.38 VSIX was installed through Antigravity's **Extensions: Install from VSIX...** flow. Antigravity visibly identified the installed extension as **X4 Forge Studio v0.0.38**.

The existing Studio tab was deliberately left open while Antigravity restarted extensions. Before restart, both the Studio badge and status bar reported managed sidecar port **56542**. After restart, the managed sidecar was **56203** and the retained Studio canvas was still fully rendered. The replacement backend and retained webview therefore remained synchronized across the exact restart path that previously produced the blank panel.

No game directory, live mod, or standing Forge directory configuration was written during this validation.
